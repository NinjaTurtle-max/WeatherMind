### 의존 규칙 (절대)
- **선행 마일스톤 미완결 상태에서 후행 착수 금지.** 1이 서야 2, 그 위에 3~6.
- 예외는 **선행 인출**뿐 — 후행 마일스톤의 일부를 앞당겨 가져오는 것은 허용한다
  (예: R10-B 뱅크 확장 = 마일스톤 3의 선행 인출). 단 인출임을 문서에 명시한다.
- **하드닝(5)을 앞세우지 않는 이유**: 미완성 제품의 하드닝은 무의미하고, 적응 루프(1)가
  나머지 전부의 전제다.
- 새 작업은 "6단계 중 어디인가"로 위치를 먼저 정한다. 완성도 판단 단위는 파일 존재가
  아니라 **"유저가 끝까지 경험 가능한 플로우"**다.

## 4. 문서 계층 (충돌 시 위가 우선)

```
전략   docs/ROADMAP.md          ← 무엇을 왜 그 순서로 (이 문서)
근거   docs/Observation_Report_*.md  ← 왜 이 항목들인가 (실사용·벤치마킹 관찰)
스펙   docs/specs/ (00~10)      ← 제품이 무엇인가
표준   docs/DEVELOPMENT_PLAN.md ← 기술 표준 결정
실행   docs/team/SPRINT_*.md    ← 누가 무엇을 어떻게 (1주 단위)
운영   docs/team/TEAM_PROCESS.md ← 어떻게 일하는가
```

- 스프린트 문서는 **로드맵 위치를 첫 줄에 명시**한다("마일스톤 N" 또는 "완성도 트랙").
- 관찰 보고서의 항목 → 스프린트 스토리 **대응표를 스프린트 문서에 남긴다**.
- 완료 시 갱신 지점은 **§1 현재 위치와 §2 상태 열 두 곳**. 다른 문서에 완료 상태를
  복제하지 않는다(중복은 단일 소유자로 해소 — `TEAM_PROCESS §2.5`).
