# 디자인 시안 (docs/design)

구현 전에 합의한 화면 시안을 둔다. **시안은 계약이 아니라 제안**이다 — 수치가
코드와 어긋나면 코드가 SSOT다. 다만 아래 「검증된 동작 계약」만은 시안이 먼저
정하고 구현이 따라간다(요구사항이 동작이라 그림으로는 표현되지 않기 때문).

## learn_session_mockup.html — 학습 세션 화면

브라우저로 바로 열면 된다(빌드·의존 없음). PC(md↑) 기준 시안이다.

> **구현 완료(2026-08-05).** `frontend/src/modules/curriculum/PcCurriculumPath.jsx` +
> `src/styles/index.css`의 `.wm-*` 블록. 계약은 `tests/learnPath.smoke.test.mjs`가
> 지킨다(`npm run test:learn-path`, CI `FRONT_TESTS` 편입).
>
> **시안에 있으나 앱에 없는 것 — 대응 API가 없다:** 섹션 부제·예상 소요시간
> (`SectionOut`은 name과 units뿐) · 섹션 보상 상자 · 상단 「학습 가이드」·「뱃지
> 보기」 버튼 · 좌측 내비의 튜터(앱 셸에 좌측 내비가 없어 우측 카드로 둔다).
> 개념 칩은 유닛의 `concept_tag`에서 파생하므로 실데이터다.
>
> **앱에서 달라진 것:** 시안은 페이지 전체를 고정했지만, 앱은 트랙만 유한 높이
> (`clamp(480px, 72vh, 680px)`)로 두고 그 안에서 스냅한다 — 앱 셸(헤더·하단 내비)과
> 아래 카드들(복습 큐·자유 세션)을 그대로 두면서 "한 화면 한 단계"를 만드는 방법이다.
> 노드 지름은 미디어쿼리 대신 **컨테이너 쿼리 + 노드 수**로 정한다(아래 참조).

### 무엇이 확정됐나

- **캐릭터 6종이 들어왔다**(2026-08-04). `frontend/public/`의 ASCII 파일명 —
  `cloud`(메인 튜터) · `drop`(학습 세션) · `sun`(게임 보드) · `bolt`(퀴즈·즉각 피드백) ·
  `typhoon`(리그) · `snow`(예보 대결). 이전 마스코트 「썬더」와 한글 파일명 png는
  전부 제거했다. 화면에서 참조할 때는 경로를 직접 쓰지 말고
  `components/Mascot.jsx`를 거친다 — 캐릭터 교체 지점을 한 곳으로 모으기 위함이다.
  **그림을 바꾸면 i18n `curriculum.tutor`(칩·이름)도 같이 본다** — 문구가 외부화돼
  있어서 그림만 갈면 물방울이 옆에 "썬더"가 남는다(실제로 그랬다).
- UI 크롬은 앱 원래 파란색(`sky-600 #0284C7` 계열). 주황은 태양이 본체에만 쓴다.
- 단계 구성은 `database/seed/units.json`을 그대로 따른다 — 4섹션 12유닛
  (하늘 읽기 3 · 공기의 힘 3 · 큰 바람 2 · 도시와 기후 4). 유닛명·`concept_tag`·
  `kind:"board"` 표식(🧩)까지 시드와 일치시켰다.
- **경로는 흰 배경 위 세로 지그재그**다(2026-08-04 최종). 자연 배경·기상 기호는
  전부 걷어냈다 — 배경 없이 길과 노드만 남긴다. 개념어는 하단
  「이 단계에서 배우는 것」 스트립에만 둔다.
  (중간에 섹션별 자연 배경안이 있었으나 폐기했다. 히스토리는 이 파일의 git log 참조.)
- 섹션 보상 상자도 **길 위의 한 칸**이다 — 옆에 붙은 카드가 아니다.
- **노드 밑에 라벨을 두지 않는다**(2026-08-04). 아이콘만 크게 두고 유닛명은
  `title`/`aria-label`로 남겨 호버·스크린리더에서 확인한다. 현재 유닛명은 트랙
  하단 진도 바가, 단계 요약은 「이 단계에서 배우는 것」 스트립이 이미 보여준다.
- **「이 단계에서 배우는 것」은 접힌다.** 접으면 눈썹 줄만 남고, 한 번 접으면 모든
  단계에 함께 적용된다(단계마다 따로 접게 하면 스크롤할 때마다 다시 접어야 한다).
- 튜터는 좌측 내비 하단 한 곳에만 둔다. 진도 바 옆에도 있었으나 중복이라 뺐다.

### 검증된 동작 계약 (구현 시 반드시 유지)

사용자 요구가 "고정된 주변 패널 + 학습 트랙만 스크롤"이라, 이건 그림이 아니라
동작이다. 시안에서 5개 해상도(1024·1280·1440·1600·1920)로 실측해 통과시켰다.

| 계약 | 측정 방법 | 기대값 |
|---|---|---|
| 페이지 자체는 스크롤되지 않는다 | `documentElement.scrollHeight - clientHeight` | 0 |
| 가로 스크롤 없음 | `scrollWidth - clientWidth` | 0 |
| 스크롤바 비표시 | `scroller.offsetWidth - clientWidth` | 0 |
| 트랙 위에서만 휠이 먹는다 | 좌측 내비 위 휠 → `scroller.scrollTop` 불변 | 불변 |
| 한 화면에 한 단계 | 스냅 지점마다 보이는 `.stage` 수 | 정확히 1 |

구현에서 밟기 쉬운 함정 세 가지(시안에서 실제로 밟았다):

1. **그리드 칸의 `min-height:auto`** — 세 칸(내비·본문·레일) 모두 `min-height:0`
   으로 눌러야 한다. 안 그러면 본문이 내용만큼 늘어나 셸을 밀어내고 페이지가
   같이 스크롤된다(시안 초기값에서 170px 밀렸다).
2. **`overscroll-behavior:contain`** — 트랙 끝에서 페이지로 스크롤이 전파되는 걸
   막는다. 이게 없으면 "주변은 고정" 요구가 트랙 끝에서 깨진다.
3. **한글 `word-break`** — 기본값은 글자 단위로 끊어서 "태어나는 / 가"가 된다.
   유닛명에는 `word-break:keep-all`이 필요하다.

### 세로 경로에서 지키는 것

- **노드 좌표를 상수로 박지 않는다.** 섹션마다 노드 수가 3·3·2·4(+보상)로 달라
  손으로 찍으면 리듬이 어긋난다. 가로 흔들림은 노드 인덱스 사인으로 구하고,
  연결선은 렌더 후 실측 좌표로 그린다(리사이즈 시 다시 그린다).
- **길은 스냅 경계를 넘어 이어진다.** 각 단계의 첫·끝 노드에서 이웃 단계의 끝
  노드 쪽으로 선을 뻗어, 한 화면 한 단계로 스냅되면서도 하나의 길로 보이게 한다.
- **`translateX(%)`를 쓰지 말 것.** 백분율이 컨테이너가 아니라 자기 자신의 폭
  기준이라 지그재그가 거의 움직이지 않는다(실제로 밟았다). px 진폭을 곱한다.
- **보상 상자도 노드다.** 진도 판정용 유닛 인덱스와 위빙용 노드 인덱스를 따로
  세지 않으면 보상 칸이 "현재 유닛"이 된다(실제로 밟았다).
- **연결선 SVG는 `position:absolute`**라 위치 없는 형제(헤더·정보 스트립) 위로
  그려진다. 그 둘에 스태킹을 줘서 선이 뒤로 가게 한다.
- **노드 크기는 세로 공간이 정한다.** 시안은 `max-height` 미디어쿼리로 86 → 74 →
  66 → 58px까지 줄인다. **앱 구현은 미디어쿼리를 쓰지 않는다** — 높이만 보면 4칸
  섹션이 2칸 섹션과 같은 지름을 받아 넘치기 때문이다. 필요 높이가
  `dot * (1.18n - 0.18)`이므로 컨테이너 쿼리(`cqh`)와 노드 수(`--n`)로 역산한다:

  ```css
  --dot: max(44px, min(86px, calc((100cqh - var(--chrome)) / (1.18 * var(--n) - 0.18))));
  ```

  `--chrome`(머리말+소개 스트립+진도 바)은 접기 상태에 따라 210 ↔ 150px로 바뀐다 —
  접으면 경로가 쓸 높이가 늘어나므로 아이콘도 같이 커져야 한다.
- **길이가 모자라면 아이콘이 아니라 간격을 줄인다.** `--gap`은 `--dot`의 비율
  (`.18`)이다. 지그재그라 노드가 좌우로도 벌어지므로 세로 간격이 좁아도 길로
  읽힌다. 검증 기준은 **"5칸 단계에서 위 소개 스트립·아래 진도 바와의 여유가
  각각 ≥ 10px"** — `.vpath` 박스 기준 넘침이 아니라 **실제로 가리는 상대와의
  간격**을 재야 한다(박스 안에 들어가 있어도 스트립에 가려 잘려 보인다).
  노드의 시각적 범위에는 그림자 5px과 현재 노드 바깥 링 8px이 포함된다.
  실측(7해상도 × 4단계) 최소 여유 20px.
- 실측 스크립트에서 `scrollIntoView()`를 쓰면 안 된다 — `.scroller`에
  `scroll-behavior:smooth`가 걸려 있어 애니메이션 중간값을 잰다. `scrollTop`을
  직접 넣는다.

## board_mockup.html — 대기 보드 **플레이 화면**

보드는 앱에서 두 화면이다. **이 시안은 ②만 다룬다.**

| | 화면 | 소유 | 시안 |
|---|---|---|---|
| ① | 퍼즐 목록 — `GET /board/puzzles` 카드 목록, 구름 0이면 카드 비활성 | `BoardPage.jsx` | **없음(현행 유지)** |
| ② | 퍼즐 플레이 — 진입한 퍼즐 하나를 푸는 화면 | `AtmosphereBoard.jsx` | 이 파일 |

**①은 새로 그리지 않기로 했다**(2026-08-05 결정). 지금 구현으로 두고, 카드를
누르면 ②(이 시안)로 들어간다. 「미션들」은 사라진 게 아니라 ①에 있다 — 시안을
보고 "미션이 어디 갔냐"는 질문이 실제로 나왔으므로 여기 적어 둔다.

「요소가 너무 많다, 단순하게 주요 기능만」이 출발점이다. 화면을 좌(팔레트)·중(지도)·
우(미션) 3단으로만 나누고, 실제 API가 없는 장식은 넣지 않았다.

### 우측 「이번 미션」이 그리는 것 = 서버 `template_json`

| 시안 요소 | 서버 필드 |
|---|---|
| 목표 현상·존 | `goal_conditions` |
| 가이드 단계 | `guide_steps` (`mode == "guided"`일 때만) |
| 난이도 배지 | `mode`·`level_group`에서 산출(R7-02 §3.5) |
| 보상 XP | 판정 응답 |
| 힌트 | **규칙표에서 생성** — 아래 참고 |

⚠️ **문항 저작 데이터의 `hints`는 화면에 쓰지 않는다.** 시드 문구가 정답 배치·
수치를 그대로 알려줘서 "정답 배치 미공개" 계약을 깬다. 시안의 힌트도 규칙표
기반 문구다(`AtmosphereBoard.jsx` 주석 참조).

### 무엇이 확정됐나

- **판정 권위는 서버**라는 걸 화면이 말한다. 하단 「판정」 카드가 "화면에 보이는
  「예상 현상」은 미리보기일 뿐"이라고 명시한다 — `board_rules.json`으로 서버가
  재계산하는 실제 동작과 어긋나 보이지 않게 하기 위함이다.
- **팔레트는 퍼즐마다 2종**이다(시드 기준). 요소 전체를 늘어놓지 않는다.
- **구름 에너지는 미통과일 때만 1 소모**(R10 전환)라 하단에 그 조건을 적어 둔다.
- 지도 좌표계는 앱과 동일하다 — viewBox 100×80, 시드 좌표는 y만 0.8 사영.
  존 마커는 `left:x% / top:y%`로 놓으면 같은 자리에 떨어진다(정규화 y를 100으로
  나눈 값 = userSpace y를 80으로 나눈 값이라 그대로 쓸 수 있다).
- **지형은 앱과 문자 단위로 같아야 한다.** 시안이 앱과 다른 지도를 그리면 시안을
  볼 이유가 없다.

### 참고 이미지에서 뺀 것

대응 API가 없어서 뺐다 — 지역·시간 드롭다운, 재생 컨트롤, 최근 실험 목록·통계,
구름 보상 애니메이션. 나중에 넣을 때는 API부터 확인할 것.

### 존 좌표를 고칠 때

**이름과 좌표의 짝을 반드시 확인한다.** 정규식 lookahead로 치환하다가 서해상에
영동·동해의 좌표가 들어가 바다 존이 육지 한가운데에 놓인 적이 있다(검증
스크립트의 `isPointInFill` 육지/바다 대조가 잡았다). 블록 단위로 자기 `.zname`을
읽어서 붙이고, 고친 뒤에는 4개 전부 기대값과 대조한다.

## gen_peninsula.py — 보드 지도 지형 생성기

`frontend/src/modules/board/PeninsulaMap.jsx`의 한반도 실루엣·부속 도서·능선과
`database/seed/board_regions.json`의 존 좌표를 **한 파일에서** 뽑는다. 넷은 같은
확대 배율을 타므로 하나만 손으로 고치면 지형과 존이 조용히 어긋난다(렌더 테스트는
좌표를 assert하지 않는다). `python3 docs/design/gen_peninsula.py`로 출력한다.

- **지리 정확도가 기준이 아니다.** 조작 보드다 — 서해안 리아스식 굴곡 같은 건
  버리고 뭉툭한 실루엣만 남긴다.
- **꺾임 없는 곡선은 저주파 푸리에로 보장한다.** 윤곽 15점을 복소 신호로 보고
  낮은 K차 하모닉(K=5)만 남긴다. 유한 삼각급수라 C∞ — 꺾이는 점이 존재할 수 없다.
- **"각졌다"는 최소 곡률반경으로 재야 한다.** 다각형의 최대 방향변화(도)는 샘플
  간격에 딸려 움직여서 같은 곡선도 촘촘히 재면 작게 나온다. 실측 비교:
  원본 다각형 0.9 · Chaikin 모서리깎기 2.9 · **푸리에 K=5 9.4**(다각형 기준).
  브라우저에서 실제 렌더된 곡선을 `getPointAtLength` 900샘플로 재면 **9.0**이다
  — 다각형 값과 렌더 값을 섞어 적지 말 것. 100폭 지도에서 반경 2.9는 각으로 읽힌다.
- **가로로 키우면 반도로 안 읽힌다.** 사영이 y를 0.8로 누르므로(`VIEW_H/100`)
  정규화에서 정사각이면 화면에서는 납작해진다. x는 두고 y만 늘린다.
- **존을 프레임 가장자리로 밀지 말 것.** 기단 유동 화살표가 오버레이 블리드 범위
  `[-20,120]`를 넘어 `test:overlay`가 깨진다(x=8.7로 밀었다가 실제로 깨뜨렸다).
- **서해상은 바다 위, 나머지 셋은 육지 위**여야 한다. `isPointInFill`로 실측한다.
