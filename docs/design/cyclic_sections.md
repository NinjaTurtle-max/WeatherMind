## 0. 한 줄 요약

기상 코스의 섹션을 주제 5종에서 **지식 단계(`knowledge_level`) 10종**으로 바꿨다.
섹션 k = kl k이고, **개념 8종이 10개 섹션을 가로질러 재등장**한다(= 순환식).
유닛은 손으로 정하지 않고 **(개념 × kl) 격자의 문항 실측에서 파생**했다.

**⚠️ 판 3 (2026-08-12 오후) — 유닛을 칸에 1:1로 묶지 않는다.**
판 1은 칸 하나에 유닛 하나를 묶어 quiz 87유닛이 됐고, 유닛 1회전이 비board 문항의
**45%밖에 쓰지 못했다**. 클라이언트 지적("유닛이 늘어나면 경로를 늘리면 되잖니")에
따라 **한 칸을 여러 유닛으로 쪼개고 선형 사슬로 잇는다**. 동시에
`UNIT_SESSION_SIZE`가 **5 → 4**로 바뀐다(담당 F) — 이 문서의 모든 산수는 4 기준이다.

| | 종전 | 판 1 | **판 3(현재)** |
|---|---|---|---|
| 기상 섹션 | 5 (주제) | 10 (지식 단계) | 10 (지식 단계) |
| 기상 유닛 | 16 | 85 | **138** (quiz 133 · board 5) |
| 기초과학 | 3섹션 8유닛 | 3섹션 8유닛 | **3섹션 99유닛** (quiz 98 · board 1) |
| 전체 | 8섹션 24유닛 | 13섹션 93유닛 | **13섹션 237유닛** |
| 문항 소진율 | — | 45% | **97.7%** |

**문항 소진율** = (quiz 유닛 수 × `UNIT_SESSION_SIZE`) ÷ 유닛 풀이 볼 수 있는 비board
문항 수 = **231 × 4 = 924 / 946 = 97.7%** (live-slot 20건을 포함한 비board 966건
기준으로는 **95.7%**). 남는 22건은 개념별 나머지(각 개념 T mod 4)라 어떤 배분으로도
유닛 한 개를 더 만들 수 없다.

기존 93유닛은 **하나도 지우지 않았다** — 쪼개진 칸의 **첫 유닛이 기존 id를 승계**한다

> 섹션을 **뒤로 보내고 알파벳순으로** 정렬한다 — 시드만 바꾸고 `SECTION_ORDER`가
> 옛 8종에 머물면 새 10섹션이 전부 미등재가 되어 「고등학교…·기상청…·중학교…·초등…·

## 4. 유닛을 만든 규칙 · 만들지 **않은** 칸

### 4.1 규칙 (전건 기계 적용 — 예외 없음)

1. **개념별 유닛 예산** `U_c = floor(T_c / 4)`. `T_c`는 그 개념이 가진, 유닛 풀이 볼 수
   있는 비board 문항 총량. **올림이 아니라 내림**인 이유는 올리면 마지막 유닛이 자기
   몫 4문항을 못 받기 때문이다(빈 세션 방지 — L2 결함이 재발하는 자리).
2. **칸 배분**: `U_c`를 그 개념의 10칸에 `n_cell / 4`의 **최대잉여법**으로 나눈다.
   **칸당 최소 1** — 자격 칸은 유닛 0개가 되지 않는다.
3. **자격 칸**: 칸 문항이 4건(`UNIT_SESSION_SIZE`) 이상이거나, **kl ±1 창**의 합이
   4건 이상. 실측상 140칸 전부가 자격을 얻는다(가장 얇은 칸이 typhoon×kl3 = 2건,
   ±1 창 13건).
4. **칸 배분의 상한은 그 칸의 문항 유형 수**다. 부제가 유형에서 나오므로(§4.4) 유형보다
   많이 쪼개면 한 칸에 같은 부제가 두 번 생긴다. **실측상 이 상한은 한 번도 물리지
   않았다** — 최대 분할이 4인데 어느 칸도 유형이 4종 미만이 아니다.
5. **board 유닛은 새로 만들지 않았다** — 재배치만 했다(§4.3). board 풀은 개념당 1~12건이라
   쪼갤 여유가 없다.
6. 섹션 안의 순서는 개념 고정 순서(기존 5섹션의 교육 순서를 편 것):
   `pressure_front → air_mass → typhoon → heat_island → co2_climate → anomaly →
   wildfire_weather → flood_response`. **한 칸의 유닛들은 그 안에서 연속**이고,
   board 유닛은 자기 개념 quiz 묶음 바로 뒤.
7. 선행은 **단일 사슬**이다 — 칸 안에서 이어지고(`u1 → u2 → u3`), 칸이 끝나면 다음 칸의
   첫 유닛으로, 섹션이 끝나면 다음 섹션 첫 유닛으로. 기상 코스 루트는 하나
   (`w01-pressure-front`).

### 4.2 만들지 않은 칸

**quiz는 0칸이다.** 규칙 ③(±1 구제)이 140칸 전부를 살렸다.

만들지 않은 것은 **board 칸 75개**다(8개념 × 10섹션 = 80칸 중 기존 5종이 앉은 5칸을
뺀 나머지). 사유는 두 가지다.

- **kl 6~10 (40칸)**: board 문항이 그 단계에 **사실상 0건**이다. 만들면 유닛 풀이
  통째로 비어 `TestZeroItemUnitSessionIsUnreachableOnThetaPath`가 즉시 운다.
- **kl 1~5의 남은 35칸**: 개념별 board 총량이 1~12건이라, 유닛을 더 만들어도
  **같은 풀을 나눠 갖는 것**뿐이다(§5-①). 특히 `co2_climate`는 board 1건이라
  유닛을 만들면 `test_curriculum_band_fallback::test_가장_얇은_유닛도_1건_이상이다`의
  부분집합 핀이 깨진다 — 그 파일은 담당 C의 소유가 아니므로 아예 만들지 않았다.

### 4.4 유닛 id·제목 규칙 — 부제는 **그 묶음의 앵커 문항 유형**에서 나온다

한 칸을 k유닛으로 쪼갤 때, 그 칸의 문항을 유형별로 갈라 **많은 유형 순으로 k개를
앵커**로 잡고 나머지 유형을 라운드로빈으로 채운다. 유닛의 부제는 자기 앵커 유형이다.

| 문항 유형 | 부제 | id 접미 |
|---|---|---|
| multiple_choice | 골라내기 | `-mc` |
| cloze | 빈칸 채우기 | `-cloze` |
| short_answer | 직접 답하기 | `-short` |
| match | 짝 맞추기 | `-match` |
| ordering | 순서 세우기 | `-ordering` |
| slider | 값 맞히기 | `-slider` |

**「개념 ①/②/③」식 서수 파생을 쓰지 않은 이유**가 이것이다 — 부제가 **그 칸의 문항
구성에서 읽힌 값**이고, 어느 유닛이 어느 부제를 받는지도 데이터가 정한다. 저작해 넣은
문구는 위 6줄뿐이고 유닛마다 새로 짓지 않는다.

⚠️ **자유 텍스트에서 키워드를 뽑는 방법은 실패해서 버렸다.** 문항 본문·정답·해설에
TF-IDF(도메인 어휘 필터 포함)를 돌려 봤으나 한국어 형태소 분석기 없이는 「발달한다」·
「때문이다」·「저장했다」 같은 활용형이 걸러지지 않았고, 어휘표 용어만 허용하면
194묶음 중 74묶음이 아무것도 못 건졌다. **없는 축을 만들지 않고 실재하는 축(유형)을
썼다.**

- **id**: 칸의 첫 유닛은 **기존 id를 승계**한다. 둘째부터는
  `{첫 유닛 id}-{유형 접미}` (예 `read-sky-pressure-mc`, `w08-pressure-front-match`).
  기초과학의 새 칸은 `{concept}-kl{NN}-{유형 접미}` (예 `pressure-basics-kl01-mc`).
- **제목**: 원 24유닛의 **손저작 제목은 그대로**다. 나머지는
  `{개념 표시명} · {부제}` — 개념 표시명은 **2단**이다(kl1~3 쉬운 말 / kl4~10 정식 용어).
  `기단`(`introduced_at=4`)이 kl1 제목에 들어가는 사고를 막기 위해서고, 생성기가
  `level_vocabulary.json`으로 **제목 전건을 재검사**한다(임계는 배경 어휘 용법이므로
  `name_ok_from`, 없으면 `introduced_at` — `docs/specs/12` §7.4와 같은 판정식).
  현재 위반 0건. 제목은 **한 섹션 안에서 유일**하다(생성기가 단정). 다른 섹션과는
  겹칠 수 있다 — 섹션 머리글이 단계를 말하므로 화면에서 구분된다.

| 개념 | kl1~3 표기 | kl4~10 표기 |
|---|---|---|
| pressure_front | 높은 기압과 낮은 기압 | 기압과 전선 |
| air_mass | 성질이 다른 공기 덩어리 | 기단과 변질 |
| typhoon | 태풍 | 태풍 |
| heat_island | 도시의 더위 | 도시 열섬 |
| co2_climate | 이산화탄소와 기후 | 온실효과와 이산화탄소 |
| anomaly | 달라지는 기후 | 이상기후와 평년값 |
| wildfire_weather | 산불이 나기 쉬운 날 | 건조·강풍과 산불 기상 |
| flood_response | 큰비가 올 때 | 호우와 침수 대응 |
| temperature_heat | 온도와 열 | 온도·열과 비열 |
| radiation_budget | 햇빛과 지구의 온도 | 태양복사와 에너지 수지 |
| pressure_basics | 공기의 무게와 기압 | 기압의 연직 분포 |
| density_buoyancy | 밀도와 뜨는 힘 | 밀도·부력과 대류 |

| energy_transfer | 열이 옮겨 가는 길 | 전도·대류·복사 |

### 4.5 기초과학 3섹션 — 섹션은 주제인데 칸은 단계다

기초과학은 섹션이 지식 단계가 아니라 주제라 **가로 축(단계)이 화면에 없다**. 그래도
문항 400건이 kl 1~10에 퍼져 있어 칸은 기상과 똑같이 (개념 × kl)로 센다. 그래서
기초과학 유닛의 제목만 **단계를 자기 안에 싣는다**:
`{개념 표시명} · {단계 표시명} · {부제}` (예 `공기의 무게와 기압 · 초등 3~4학년 · 골라내기`).

한 개념의 칸들은 그 개념의 기존 유닛이 있던 섹션에 전부 들어가고, 섹션 안에서 kl
오름차순으로 늘어선다. 기존 8유닛은 자기 개념의 **kl1~3 중 가장 두꺼운 칸**의 첫
유닛 자리를 승계한다(같은 개념에 유닛이 둘이면 두꺼운 순으로 두 칸). 기초과학은
**섹션 간 선행이 없다**는 specs/11 §2 규약대로 섹션마다 루트가 하나씩 남는다.

`section_meta.topics`는 ⑴ 그 단계에서 **처음 도입되는 용어**
(`level_vocabulary.introduced_at == kl`, 표기 변형은 하나만) → ⑵ 모자라면 그 섹션에서
**문항이 가장 두꺼운 개념**의 표시명 순으로 4개를 채웠다. 두 소스 모두 데이터라
섹션마다 값이 갈린다.

## 5. ⚠️ 설계 전제 중 **데이터가 반박한 것** — PM 판정 필요

### ① 가장 중요 — 지금 이 재구조화는 **런타임에 아무 효과가 없다**

`curriculum_service._unit_content_pool`은 유닛 문항 풀을 **`concept_tag` + `kind`
(board/비board)로만** 고른다. `knowledge_level`은 필터가 아니라
`rank_by_knowledge_level`의 **정렬 표적**으로만 쓰이고, 그 표적은
**유저의 θ**에서 나온다(`theta_to_knowledge_level(overall_theta(...))`) — **유닛에서
나오지 않는다.**

> 결과: `초등 3~4학년` 섹션의 `w01-pressure-front`와 `학부 고학년` 섹션의
> `w09-pressure-front`는 **완전히 같은 풀에서 완전히 같은 순서로** 5문항을 뽑는다.
> 배선하지 않으면 10섹션은 **화면상의 장식**이다.

**PM에게 제안하는 배선**(한 함수, 마이그레이션 불필요 — kl은 섹션명에서 파생한다):

```python
# curriculum_service.py — SECTION_ORDER 바로 아래
#: 섹션 → 지식 단계. 기상 코스 섹션은 이름 자체가 단계라 별도 컬럼을 두지 않는다
#: (units.json에 knowledge_level 필드를 넣으면 같은 사실이 두 곳에 적힌다).
SECTION_KNOWLEDGE_LEVEL = {name: i + 1 for i, name in enumerate(SECTION_ORDER[:10])}

def unit_target_level(unit, fallback: int | None) -> int | None:
    """유닛의 표적 단계 — 섹션이 단계를 말하면 그것이 이기고, 아니면 θ 파생값."""
    return SECTION_KNOWLEDGE_LEVEL.get(getattr(unit, "section", None), fallback)
```

`_unit_content_pool`의 `target_level`을 이 값으로 바꾼다.
**반드시 정렬 표적으로만 쓰고 하드 필터로 만들지 말 것** — 같은 파일의
`test_지식수준_고정반경으로는_굶주림이_안_풀린다`가 "고정 kl 창은 밴드 공백을 단계
공백으로 옮길 뿐"임을 실측으로 못 박아 두었다. 위 §4.1의 5건 규칙은 **굶주림 방지가
아니라 세션 충실도**를 위한 것이다(정렬만 쓰면 굶지는 않는다 — 상위 5건이 표적 단계에서
나오느냐의 문제다).

### ② 「상위 밴드는 폭이 좁다」는 **quiz 문항 수에서 나오지 않는다**

kl별 문항 수는 98~104로 거의 균일하다(`1:98 … 10:100`). 규칙을 그대로 돌리면 10섹션이
전부 quiz 8유닛으로 **같은 폭**이 나온다. 좁아지는 것은 두 군데뿐이다.

- **(a) board 축(데이터가 말한다)**: board 문항이 kl6 이상에 없어서 board 유닛이
  하위 밴드에만 존재한다. 위 §3.1.
- **(b) 밴드 폭 해석(재해석 제안 — PM 판정)**: 대장의 "상위 밴드는 폭이 좁고 유닛은
  2배"를 **학령 밴드가 쪼개지는 폭**으로 읽으면 이미 참이다.
  `KNOWLEDGE_LEVEL_BANDS`가 elementary 2칸 · middle_high 2칸 · adult 2칸 ·
  **expert 4칸**이므로, expert 학습자는 **폭 1짜리 섹션 4개**를 지나고 초등 학습자는
  폭 1짜리 섹션 2개를 지난다 — 상위가 「폭이 좁고 유닛이 2배」다.
  이 해석을 채택하면 CO-G1은 추가 저작 없이 닫힌다. **채택 여부는 PM 판정 사항**이고,
  이 문서는 종전 해석("상위 섹션의 개념 폭을 좁힌다")을 강제로 만들지 않았다 —
  없는 콘텐츠로 유닛을 만들면 L2 결함(0문항 세션)이 재발하기 때문이다.

### ③ 유닛 수는 **칸 수가 아니라 문항 수**가 정한다 (판 3의 전환)

판 1은 칸당 유닛 1개였고 그래서 유닛 수가 140칸에 묶여 있었다. 소진율이 45%였던
원인이 이것이다. 판 3은 개념별 예산 `floor(T_c / 4)`로 유닛 수를 정하므로,
**문항이 늘면 유닛이 자동으로 늘어난다** — 저작 배치가 들어올 때마다 생성기를 다시
돌리면 된다. 반대로 `UNIT_SESSION_SIZE`가 4가 아닌 값으로 다시 바뀌면 **유닛 수 전체가
그만큼 바뀐다**(5로 되돌리면 231 → 185). 이 짝은 §6-②의 계약 테스트로 묶어야 한다.

### ④ 배치고사 선해제(`placement_unlock_floor`)가 3 → 1로 줄어든다

종전에는 「하늘 읽기」 선두 3유닛이 전부 `pressure_front`라 θ 하나로 3유닛이 열렸다.
새 구조는 섹션 안에서 개념이 교차하므로 **선두 연속 구간이 1유닛**이다. 결함이 아니라
구조의 귀결이고(개념이 순환하니 당연하다), 선해제를 되살리려면 `placement_unlock_floor`가
"선두 연속"이 아니라 "개념별 최고 도달 섹션"을 보게 바꿔야 한다 — **이 설계안의 범위
밖이고 별도 판정 사항**이다.
