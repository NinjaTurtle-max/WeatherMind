## 2. 규정 — 저작권 (트랙 04)

**"표절 및 저작권 검증을 실시합니다."** 팀 간·외부 출처 대비 표절 검증 +
**"제공 계정의 개발 세션 확인"**을 거친다. AI 사용 자체는 문제없으나 **다른 팀이나
외부 출처의 코드를 그대로 사용하는 것은 불가**. AI로 생성했어도 저작권·특허·보안
책임은 면제되지 않고 **최종 책임은 참가자**에게 있다.

| 항목 | 허용 ✓ | 주의 ⚠ |
|---|---|---|
| AI 생성 코드 | Claude Code 등으로 생성한 코드 사용 가능 | 다른 팀과 **동일한 코드 그대로** 제출 금지 |
| 오픈소스 | **MIT·Apache 2.0 등 상업적 허용** | **GPL 계열은 활용 범위 제약 가능. README 명시 필요** |
| 이미지·아이콘 | CC0·Unsplash·**직접 제작** | 출처 불명 이미지·유료 스톡 무단 사용 금지 |
| 폰트 | Google Fonts·Noto Sans 등 무료 폰트 | 상업용 폰트 무단 사용 금지. **라이선스 README 명시** |
| 데이터 | 출처·활용 가능 범위 확인 | **원출처 표기 필수** |

**기상청 자료**: 공공누리(KOGL) **유형을 확인하고 출처를 구체적으로 표시**. 제1유형
(출처표시)은 출처만 밝히면 자유이용, **제2·3·4유형은 상업적 이용·변형 등 제한** 확인
필요. FAQ 보충: 기상자료개방포털 데이터는 활용 가능하되 **개별 항목의 적용 가능성은
팀이 직접 확인**해야 하고, **대용량 API는 필수가 아니며** 공공데이터포털·국가기상
위성센터 등 다른 공공 데이터도 함께 쓸 수 있다.

**마스코트 주의**: 가이드 각주에 *"기상청 상징 및 마스코트 '기상이'의 저작권은
기상청에 있습니다"*. 우리 캐릭터가 기상이와 유사하면 문제가 된다(§5 A-4).

## 3. 규정 — 보안 (트랙 04) 및 API 키 (트랙 02)

> **"API 키가 노출되면 실격입니다."**

기상청 키뿐 아니라 **외부 서비스에서 발급받은 어떤 키라도** 동일하다. 금지 4종:
코드에 직접 기입 · **GitHub 저장소에 커밋** · Slack·PR·스크린샷 노출 · 노출된 키 방치.

**키 종류가 둘이다 — 혼동하면 실격 조항에 걸린다.**

| 키 | 용도 | 유효 | 제출 |
|---|---|---|---|
| **대회 제공 키**(대용량 API) | 개발·테스트. **횟수 제한 없음** | **8/22까지** | **절대 제출 금지** |
| **팀 개인 발급 키** | **최종 제출 소스코드·구동 URL** | 자체 | 이것만 사용 |

가이드 CLAUDE.md 예시 원문: *"최종 제출 시에는 반드시 본인 개인 계정으로 발급받은
개인용 API 키를 사용합니다."* (원문 표기가 두 키를 모두 "개인용"으로 불러 혼선이
있다 — §6-Q1로 확인 예정. **실무 결론은 위 표대로 두 키를 분리 운용**한다.)

## 4. 우리 계획과의 충돌·영향 12건

### A. 🔴 "로그인 없이 열려야 한다" vs 첫 화면이 로그인 페이지

규정: *"누구나 접속해 **바로 조작**할 수 있는 웹 주소 … **로그인·결제 없이 열려야**"*.
실측: `App.jsx:44` — `if (!accessToken) return <Navigate to="/login" replace />`.
게스트 CTA는 있다(`LoginPage.jsx:12` — *"계정 없이 즉시 체험이 주 동선"*, 게스트 CTA가
첫 시선). 그래도 **심사위원이 처음 보는 화면은 로그인 화면**이고, 규정 문구의 문언적
해석은 "열면 바로 조작"이다.

**결정: 랜딩을 무인증 체험 화면으로 바꾼다.** 최소안은 루트 진입 시 **자동 게스트
발급**(`POST /auth/guest`는 이미 실 유저·실 JWT를 발급한다) 후 학습 홈으로, 로그인·
가입은 상단 링크로 내린다. R13 §2.5(진입 통합)와 같은 파일을 건드리므로 **거기에
편입**한다. 대안(현행 유지 + 데모 녹화에서 클릭 1회)은 규정 리스크를 남기므로 채택
안 한다.

### B. 🟢 프롬프트 세션 — 원재료는 이미 자동 확보돼 있다

**Claude Code가 전 세션을 자동 기록 중이다.** 실측(2026-08-06):
`~/.claude/projects/-Users-...-weathermind/`에 **11세션 · 13,482줄 · 약 46MB**,
기간 **7/07~8/06 전 구간**. 계획서 작성기부터 R13까지 빠진 구간이 없다. 산출물 ③은
"만들어야 할 것"이 아니라 **형식을 맞춰 내보내면 되는 것**이다.

남은 일은 셋뿐이다:
1. **형식** — `.jsonl`은 규정이 요구하는 `.md`/`.txt`가 아니다. 변환 필요.
2. **선별** — 요건이 "**주요** 프롬프트 세션"이다. 46MB 전량은 과다하고, 심사자가
   읽을 수 있는 단위로 라운드별 대표 세션을 고른다.
3. **비밀값 스캔** — §3 실격 조항 방어.

**현시점 스캔 결과: 실키 유출 0건**(2026-08-06 실측). Google(`AIza`+35)·
GitHub(`ghp_`+36)·OpenAI(`sk-`+20↑) 키 형태 **각 0건**, `.env`는 **git 미추적 ·
커밋 이력 없음**, `KMA_API_KEY`도 한글 플레이스홀더라 실키가 아니다. (`sk-` 원시
2,966건은 `task-`·`risk-` 등 단어 내부 오탐, `POSTGRES_USER/DB` 18,333건은 값이
프로젝트명 `weathermind`인 데서 온 오탐이다.)

> ⚠️ **이 안전은 "아직 키를 안 넣었기 때문"이다.** G0·G1·G2에서 실키를 투입하는
> 순간부터 세션에 실값이 섞이기 시작한다 — 스캔은 **8/20 내보내기 직전에 반드시
> 재실행**한다(B-2). 지금 통과했다는 사실은 그때의 보증이 아니다.

### C. 🟡 README 라이선스 인벤토리 부재 + Redis 라이선스 위험

README(96줄)에 아키텍처·실행 순서·API 개요·트러블슈팅은 있으나 **외부 리소스
출처·라이선스 절이 없다**(산출물 ④ 명시 요건). `LICENSE` 파일도 없다.

인벤토리 작성 중 **실제 위험 1건**: `docker-compose.yml:93` **`redis:7-alpine`** —
이 태그는 최신 7.x로 해석되고 **Redis 7.4+는 RSALv2/SSPLv1**(OSI 미승인, GPL보다
제한적)이다. 규정이 "GPL 계열은 활용 범위 제약 가능"이라 경고한 것보다 더 강한
라이선스가 무심코 들어와 있다. **`redis:7.2-alpine`(BSD-3) 핀 고정**을 권한다 —
우리는 Redis를 브로커·캐시로만 쓰므로 기능 손실 0이다.

폰트는 안전하다: `index.css`가 Pretendard를 **선언만 하고 번들하지 않아**
시스템 폰트로 폴백한다(웹폰트 다운로드 없음). README에 그 사실을 적으면 끝난다.

### D. 🟡 소스 zip의 "누락 시 탈락" vs "빌드 산출물 제외"

두 규칙이 반대 방향으로 당긴다: `node_modules`·빌드 산출물은 **빼야** 하고,
**소스코드 누락이 확인되면 탈락**이다. 우리는 4서비스 + 마이그레이션 + 시드 +
스크립트 + docker-compose 구성이라 **"소스"의 경계를 미리 정의**해 두어야 한다.
`.env`는 반드시 제외하되 **`.env.example`은 포함**해야 재현이 가능하다(§5 D-1).

### E. 🟡 URL 유지 기간이 8/21이 아니라 **9월 셋째 주**

ROADMAP §5.5는 8/10 배포~8/22 심사까지만 상정하고 있다. 실제로는 **시상식까지
약 6주 무중단 운영**이다. 클라우드 비용·갱신·모니터링을 그 기간으로 재산정해야 하고,
**8/22 만료되는 대회 제공 키를 쓰고 있으면 심사 이후 URL이 죽는다** — §3의 키 분리가
여기서 두 번째 이유를 얻는다(팀 개인 키는 만료되지 않는다).

### F. 🟡 배포처 자유 — 계획은 유효하나 **가이드가 전제하는 결과물과 우리가 다르다**

*"Vercel, GitHub Pages, Netlify 등 어떤 배포 방식이든 인정됩니다."* → Docker+Caddy
계획은 유효하다. **다만 그 셋에는 우리가 올라가지 않는다**는 것을 정확히 알아 둘 것:
셋 다 **정적 파일 호스팅**이라 상시 구동 서버·Postgres·Chroma·Celery beat를 얹을
자리가 없다. 프론트만 올리면 화면은 뜨지만 `POST /auth/guest`부터 전부 404다.
(GitHub Pages는 추가로 **우리 저장소가 private이라 무료 플랜에서 불가**.)

**대회가 전제하는 결과물이 다르다.** 가이드 홈은 "웹 인터랙티브 교육 콘텐츠",
트랙 02 예시는 `index.html` 한 장이다 — 계산이 브라우저에서 끝나므로 무료 정적
호스팅으로 충분하고, **그래서 대회가 인프라를 제공하지 않는 것은 그들 기준에서
모순이 아니다**(제공 대상은 Claude 팀 계정, 즉 만드는 도구까지다).

서버가 필요해진 것은 **우리 선택의 결과**다: 채점을 클라이언트에 두면 결과 주입이
가능해 보드 판정 권위가 무너지고, IRT/BKT 학습자 모델·RLS 유저 격리·리그는 서버
자산이다. 이것이 심사에서 내세울 차별점인 동시에 **리스크 비대칭**을 만든다 —
정적 페이지는 죽지 않지만 **우리는 서버가 죽으면 심사 자체가 성립하지 않는다.**
서버 확보를 8/10이 아니라 **오늘로 당긴 이유가 이것**이고, 막히면 Hetzner
6주 ~€12를 즉시 쓴다(§5 A-1). **비용 문제가 아니라 시간 문제다.**

**가이드의 실제 공백 1건**(→ §6-Q6): 규정은 "API 키 노출 = 실격"인데 정적 페이지가
기상청 API를 부르면 키가 브라우저에 드러난다. 서버리스 프록시가 사실상 필수인데
가이드는 *"키를 직접 쓰지 않습니다"*라고만 하고 대안 경로를 적지 않았다.

**§4-E 때문에 서버는 9월 중순까지 살아 있어야 한다.**

### G. 🟢 코드 프리즈 — 우리 일정이 더 엄격하다

규정 8/21 18:00 vs 우리 8/17 기능 동결. 우리가 나흘 빠르다. **단, 8/18 b 재보정과

소스 변경이 아니고, QA 중 버그 수정은 소스 변경이다. **8/21 18:00 이후에는 env
