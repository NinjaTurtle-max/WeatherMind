# 멘토링 대비 — 개발계획서(SCAN0000) 대비 이행 감사와 괴리 서사

**작성: 2026-08-05 (PM).** 원본: `docs/SCAN0000.PDF`(7/03 제출 개발계획서, 9쪽).
계획서의 AI 로직 주장 전부를 코드와 대조 실측한 결과다 — **정확 일치 다수 + 괴리 4건 +
하드 리스크 1건**. 이 문서는 괴리 4건의 서사를 확정한다.

> 원칙: **변명이 아니라 결정의 재구성.** 모든 문장은 리포지토리에 실존하는 결정
> 기록·커밋·실측 수치로 뒷받침한다. 멘토·심사위원 앞에서 "계획과 달라진 것"을 먼저
> 말하는 쪽이 신뢰를 산다 — 감추다 들키는 것의 반대.

## 0. 30초 요약 (구두 스크립트)

> "계획서의 AI 골격 — LangChain 3체인, IRT 기반 WeatherBrain, RAG 피드백, 새벽 2시
> 수집 파이프라인, RLS 격리 — 은 문구 단위로 구현돼 있습니다. 달라진 것은 넷인데
> 전부 의도된 결정입니다: 기후 탐정은 더 조작적인 형태인 대기 보드 퍼즐로 진화했고,
> 그에 딸린 이상기후 아카이브와 생성 프롬프트의 지식 주입은 키 투입 게이트에 편입돼
> 있으며, '파인튜닝'이라 적었던 것의 실체는 계획서 2-3에 명시한 대로 IRT이고 지금은
> BKT까지 확장해 합성 데이터 복원 검증을 마쳤습니다."

## 1. 괴리 ① 기후 탐정 → 대기 보드 퍼즐 (기능 전환)

**계획 원문(5쪽 3-1-②)**: 실제 이상기후 사례의 기상 데이터를 클릭·탐색하며 단서
수집 후 인과관계 추론 — 사건 제시 → 데이터 탐색 → 단서 수집 → 원인 추론 → AI 피드백.

**실측**: detective 모듈 미구현(빈 모듈은 R10에서 삭제). 대신 계획에 없던
**대기 보드 퍼즐**이 핵심 모듈로 존재(서버 채점 권위·판정 규칙 공유·12퍼즐).

**결정 경위(기록)**: `SPRINT_R3_01.md` §0 — **2026-07-20 클라이언트 제품 결정**.
"시뮬레이션은 수치 실험이 아니라 대기 보드 퍼즐 — 기상요소를 보드 위에서 움직여
실제 대기현상을 만들어내는 플레이." 탐정은 같은 결정에서 Phase 3 후순위로 미뤄졌고,
빈 자리표시자는 R10 정리에서 삭제됐다(커밋 `8d0e6e2`).

**서사(확정)**: 학습 목표 관점에서 탐정과 보드는 같은 것을 겨눈다 — **대기 현상의
인과 구조 추론**. 탐정은 결과(사례)에서 원인을 역추적하는 *읽기형*, 보드는 원인
(기단·전선·습기·일사 배치)을 조합해 결과를 만들어내는 *조작형*이다. 개발 과정에서
조작형이 학습 목표를 더 직접적으로 체득시킨다고 판단해 전환했고, 판정을 서버가
재계산하는 구조(클라이언트 결과 주입 불가)로 교육적 무결성도 확보했다.
탐정의 **소재**(실제 이상기후 사례)는 사라진 게 아니라 두 경로로 흡수된다:
`anomaly` 개념 태그 문항(현재 시드 9건) + 키 게이트에서의 사례 아카이브 복원(괴리 ②).

**예상 Q**: "탐정을 아예 버린 건가?" → **A**: "모듈로는 통합했고 학습 목표로는
보드가 승계했습니다. 이상기후 사례 기반 콘텐츠 확장은 콘텐츠 게이트(G1)에 배정돼
있고, 사례 탐구를 별도 모듈로 되살릴지는 본선 이후 사용자 데이터로 판단합니다."

> ⚠️ **아래 §2·§3은 2026-08-07(R13 3일차)에 사실관계가 바뀌었다.** 벡터 저장소
> (Chroma)와 임베딩 의존을 **철거**했다 — `anomaly_cases`는 "예약된 자리"가 아니라
> 지워졌고, 피드백 체인의 Context Injection은 벡터 검색이 아니라 `concept_tag`
> **직접 조회**다. 발표 답변은 아래 원문이 아니라 이 각주로 한다: *"3컬렉션 중 실제
> 소비처가 있던 것은 하나였고, 그 하나는 코퍼스가 8KB라 검색이 필요 없었습니다.
> 그래서 벡터 스택을 걷어내고 개념 문서를 직접 주입하도록 바꿨습니다 — 검색 실패라는
> 실패 양식이 사라져 품질은 오히려 올라갔고, 세 번째 API 키가 불필요해졌습니다."*
> 근거: `docs/specs/03_ai_chains_spec.md` §3.1.

## 2. 괴리 ② `anomaly_cases` 컬렉션 휴면 (데이터 축 미가동)

**계획 원문(3쪽 2-2·2-5)**: 과거관측 API 월별 수집 → 이상기후 사례 아카이브를
Chroma에 임베딩(RAG 활용), `anomaly_cases` 컬렉션 월별 갱신.

**실측**: 컬렉션 상수는 선언돼 있으나(`chroma_client.py:17` — 3컬렉션 중 하나)
인덱싱 태스크가 없다. 과거관측 API는 리그 정산에만 사용. 나머지 2컬렉션은 가동
(climate_concepts 시드 적재·weather_daily는 매일 02:00 celery→ai-worker 갱신 트리거).

**서사(확정)**: 괴리 ①과 **같은 뿌리** — 탐정 모듈이 후순위로 가면서 그 데이터
축이 함께 밀렸다. 방치가 아니라 대기다: 인덱싱 파이프라인 패턴은 `weather_daily`로
이미 검증돼 있어(수집→임베딩→upsert) 재사용 비용이 작고, **임베딩 키(OpenAI)가
전제**라 키 투입 게이트에 편입돼 있다. 복원 시 RAG 피드백의 검색 대상에
`anomaly_cases`를 추가하면 계획 문구가 그대로 이행된다.

**예상 Q**: "왜 컬렉션 3개라 해놓고 2개만 쓰나?" → **A**: "세 번째는 이상기후
사례 축인데, 그 소비처(탐정)가 보드로 전환되며 우선순위가 밀렸습니다. 파이프라인
패턴은 weather_daily로 이미 검증돼 있고 임베딩 키 투입 시점에 같은 패턴으로
가동합니다 — 죽은 코드가 아니라 예약된 자리입니다."

## 3. 괴리 ③ Quiz Gen의 Context Injection 부재

**계획 원문(3쪽 2-4)**: Chroma 검색 결과(기상 지식 청크)를 프롬프트에 동적 삽입해
**환각 방지** 및 답변 정확도 향상.

**실측**: Chroma 주입은 RAG 피드백 체인에만 있다(top_k=3·threshold 0.7 — 계획
그림 2와 숫자까지 일치). 생성 체인은 실황 데이터만 주입.

**서사(확정)**: 계획의 **목표**(환각 방지)는 계획에 없던 더 강한 장치로 달성 중이다
— 생성 문항 **2단 게이트**: 결정적 휴리스틱(LLM 무관) 1차 + LLM 검증 2차, 여기에
R11에서 payload 완전성 계약(값 정합 6규칙)까지 추가됐다. 주입은 "환각을 줄이는"
접근이고 게이트는 "환각을 잡아내는" 접근인데, 무키 환경에서도 작동해야 하는 우리
운영 조건에서는 게이트가 선행이 맞았다. **주입 자체는 포기가 아니라 G1 편입**:
G1의 프롬프트 개정(기초과학 태그 6종 추가)과 같은 커밋에서 RAG 체인의 검색 코드를
재사용해 생성 프롬프트에도 지식 청크를 넣는다 — 프롬프트↔스펙 동일성 가드
(`test_prompt_spec_parity`)가 이미 있어 개정이 안전하다.

**예상 Q**: "환각 방지는 어떻게 하고 있나?" → **A**: "이중입니다. 생성 후 결정적
휴리스틱과 LLM 검증의 2단 게이트가 잡아내고, 슬라이더 같은 수치형은 값 정합 6규칙
계약이 격자·범위까지 검사합니다. 계획의 검색 주입은 콘텐츠 게이트에서 추가돼
사전 방지 축을 보강합니다."

## 4. 괴리 ④ "자체 Fine-tuning 모델" 용어 (2-1 표)

**계획 원문**: 2-1 표 "WeatherBrain — 자체 Fine-tuning 모델" vs **같은 문서** 2-3
상세 "quiz_logs·weak_tags 누적 데이터 기반 IRT(문항반응이론) 모델 재학습".

**실측**: 구현은 2-3을 따른다 — IRT 2PL(순수 파이썬, `irt.py`) + celery 재학습
태스크(`retrain` → `/weatherbrain/calibrate`, 누적 로그로 난이도 b 재보정) + R11에서
**BKT 지식 추적** 확장(합성 200명 복원 검증: 파라미터 오차 0.017/임계 0.05 ·
숙련 AUC 0.929/0.85).

**서사(확정)**: 계획서 내부의 표기 불일치이고, 구현은 상세 서술을 따랐다.
"함께 성장하는 AI"(6쪽 4-1)의 실체가 정확히 이것이다 — 사용자가 풀수록 문항
난이도 추정이 재보정되고(IRT), 학습자별 숙련 전이가 추적된다(BKT). **LLM
파인튜닝을 하지 않은 것은 결점이 아니라 설계다**: 학습자 모델은 해석 가능성과
콜드스타트가 생명이라 통계 모델이 적합하고, LLM은 생성·검증·피드백에 쓴다
(이중 레이어 — 계획 2-3의 구조 그대로).

**예상 Q**: "파인튜닝 모델은 어디 있죠?" → **A**: "계획서 2-3에 명시한 대로
WeatherBrain은 IRT 재학습 모델입니다. 2-1 표의 'Fine-tuning'은 그 재학습을 가리키는
축약이었고, 정확한 용어로는 자체 통계 모델의 지속 재보정입니다. LLM을 파인튜닝하는
대신 학습자 모델(해석 가능·콜드스타트 강함)과 LLM(생성·피드백)을 분리한 이중
레이어이고, R11에서 BKT까지 확장해 복원 검증 수치를 갖고 있습니다."
