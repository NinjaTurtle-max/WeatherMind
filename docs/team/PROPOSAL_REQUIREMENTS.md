## §1 개발 목적 및 필요성 (※주제 적합성)

### 1-1. 기존 기상교육의 한계
- 교과서·영상 중심의 일방향 교육과 정적 콘텐츠로 실시간 기상 학습 한계
- AI 기반 예측·시뮬레이션 등 데이터 중심의 체험형 학습 환경 부족
- 전문 기상 데이터의 활용 장벽으로 실제 데이터를 활용한 학습 기회 부족

### 1-2. 개발 목적 및 목표
- '오늘의 날씨'가 매일 새로운 학습 콘텐츠가 되는 플랫폼 구현
- 학습자 이해도·오답 패턴 분석 적응형 학습 구조와 수준별 체험 환경 제공
- 게이미피케이션과 탐구형 콘텐츠를 결합한 AI 기반 기상 에듀테크 플랫폼 개발

### 1-3. 기대 교육 효과
- 실시간 날씨 기반 퀴즈와 스트릭·XP 시스템으로 지속적인 학습 습관 형성
- 기상 데이터 탐색·시각화와 AI 기반 학습을 통해 데이터 해석·활용 능력 향상
- **시뮬레이션으로 기후변화의 영향을 체험**하고 환경 문제에 대한 이해 증진

## §2 적용 기술 및 실현 구체성 (※실현 가능성)

### 2-1. 전체 기술 스택

| 구분 | 기술 | 역할 |
|---|---|---|
| 프론트엔드 | React + Vite | **퀴즈·탐정·시뮬레이터·리그 모듈** |
| AI | WeatherBrain + LangChain | Router Chain · RAG Chain · Quiz Gen Chain |
| 백엔드 | FastAPI + Celery Beat | REST API, 일일 자동 스케줄러 |
| 데이터베이스 | ① PostgreSQL ② Redis ③ Chroma DB | ① 학습이력·RLS 사용자격리 ② 캐시·세션·Celery 브로커 ③ 벡터 임베딩·RAG |
| 인프라 | Docker Compose | **7개 컨테이너**(frontend · backend · weatherbrain-worker · celery · postgres · redis · chroma) |
| AI 모델 | ① WeatherBrain ② **Gemini 3.1 Flash-Lite** ③ text-embedding 3-small | ① 자체 Fine-tuning 모델 ② Quiz Gen · RAG 피드백 ③ Chroma DB 벡터화 |

### 2-2. 기상청 API 연동 상세
- 단기예보 API: Celery Beat로 **매일 새벽 2시** 최신 예보 자동 수집, Redis(**TTL 1시간**) 캐싱 후 오늘의 퀴즈·학습 콘텐츠 생성
- 중기예보 API: **주 1회** 3~10일 예보 수집, 주간 기상 예측 리그 기준 데이터 활용
- 과거관측 API: **월별** 관측자료 수집, 이상기후 사례 아카이브를 Chroma DB에 임베딩하여 AI 검색(RAG) 활용
- API 장애 대응: Redis 캐시 기반 자동 복구(fallback)와 중복 호출 방지

### 2-3. AI 이중 레이어 구조 (WeatherBrain + Gemini 3.1 Flash-Lite)
- **WeatherBrain**: `quiz_logs`와 `weak_tags` 누적 데이터 기반 **IRT(문항반응이론)** 모델 재학습, 문제 난이도와 학습자 수준 동시 추정, Router Chain으로 AI 모듈 분기
- **Gemini 3.1 Flash-Lite**: Quiz Gen Chain(오늘 날씨 기반 문제 자동 생성), RAG Chain(오답 개념어 기반 Chroma DB 검색·피드백 생성)
- **text-embedding-3-small**: 기상청 데이터, 교과 개념, 이상기후 사례 텍스트를 벡터로 임베딩하여 Chroma DB 적재
- **LangChain**: Router Chain, RAG Chain, Quiz Gen Chain

### 2-4. 프롬프트 엔지니어링 구조
- **System Prompt**: 역할(기상교육 전문 AI), 톤(학습자 눈높이), 출력 형식(JSON 스키마)을 고정해 일관된 응답 생성
- **Few-shot Examples**: 객관식·슬라이더·예측형 문제 유형별 예시를 제공, 일관된 문제 생성 및 출력 형식 유지
- **Context Injection**: Chroma DB 검색 결과(기상 지식 청크)를 프롬프트에 동적으로 삽입하여 **환각 방지** 및 답변 정확도 향상
- **Output Parser**: JSON 응답을 정형 데이터로 변환해 프론트엔드 UI에 자동 렌더링

### 2-5. 데이터베이스 설계 (사용자 격리 포함)
- **PostgreSQL**: `users`·`quiz_logs`·`weak_tags`·`attendance`·`league_results` **5개 핵심 테이블** 구성, **Row-Level Security(RLS)**를 적용해 `user_id` 기반 사용자 데이터 격리
- **Chroma DB**: `weather_daily`(매일 갱신), `climate_concepts`(교과 개념, 초기 적재), `anomaly_cases`(이상기후 사례 월별 갱신) **3개 컬렉션**
- **Redis**: 기상청 API 응답 캐싱(TTL 1시간), 세션 관리(TTL 7일), Celery 메시지 브로커, 일일 문제 캐시(TTL 24시간) 운영

### 2-6. Docker Compose 배포 구조 및 URL 시연 환경
- **7개 컨테이너**: frontend(React+Nginx), backend(FastAPI+Uvicorn), weatherbrain-worker(Fine-tuning 모델+LangChain+Chroma), celery(Beat+Worker), postgres, redis, chroma
- **단일 명령(`docker compose up`)으로 전체 서비스 기동**, 클라우드 서버 배포 후 **공개 URL 제공**
- 발표 당일 **심사위원 기기에서 공개 URL로 즉시 접속·시연 가능한 환경** 구축
- 모든 서비스 컨테이너화로 동일한 실행 환경과 높은 재현성 확보, 로컬 환경 의존성 최소

### 2-7. 개발 일정 (대회 일정 내 핵심 기능 구현)
- **7.3~7.22(교육)**: 기상청 API 연동, PostgreSQL 스키마 확정, React 기본 UI 구현
- **7.23~8.7(사전 개발)**: 오늘의 퀴즈 모듈 완성, WeatherBrain 초기 모델 학습 및 Gemini 3.1 Flash-Lite RAG 체인 구현, Docker Compose 구성
- **8.7(중간 점검 제출)**: 퀴즈 모듈 및 RAG 피드백, 기본 XP·스트릭 기능 시연 가능
- **8.8~8.20**: **탐정·시뮬레이터·리그 모듈 구현**, 오답 패턴 분석 완성

## 🔴 §3 체험 요소 및 학습 효과 (※체험·참여형 설계 · ※학습 효과)

### 3-1. 4개 인터랙티브 모듈 — 사용자 조작·탐구 구조

> **이 절이 「체험·참여형」 배점의 근거 조항이다.** 네 모듈이 각각 「사용자 조작 ·
> 상호작용 흐름 · 학습 성과」 3항으로 적혀 있으므로, 감사는 **모듈별로 그 3항이
> 화면에 있는가**를 본다.

#### ① 오늘의 기상 퀴즈 (Duolingo 오마주)
- **사용자 조작**: 기상청 실시간 데이터 기반 **객관식·주관식·슬라이더형** 퀴즈 풀이
- **상호작용 흐름**: 접속(출석 체크) → 문제 제시 → 답변 입력 → AI 피드백
- **학습 성과**: 오늘 날씨의 과학적 원리·기상 용어 학습, 일일 기상 리터러시 향상

#### ② 기후 탐정 (Brilliant.org 오마주)
- **사용자 조작**: 실제 이상기후 사례(예: 2024년 7월 서울 집중호우)의 기상 데이터를 **직접 클릭·탐색**하며 **단서 수집** 후 **인과관계 추론**
- **상호작용 흐름**: 사건 제시 → 기상 데이터 탐색 → 단서 수집 → 원인 추론 → AI 피드백 및 추가 탐구 제안 → 사건 해결
- **학습 성과**: 이상기후 발생 원리 이해, 과학적 추론 능력 및 기상 데이터 해석 역량 향상

#### ③ 기후 시뮬레이터 (체스 전략형)
- **사용자 조작**: **CO₂ 농도·기온·강수량 등 기후 변수를 직접 조절**하며 기후 변화 시나리오를 실시간으로 비교·체험
- **상호작용 흐름**: 변수 선택 → 슬라이더 조작 → 그래프 즉시 반영 → 결과 확인 → **여러 시나리오 비교 및 최적 전략 탐색**
- **학습 성과**: 기후 변수 간 인과관계 체험적 이해, 기후위기 대응의 중요성 인식

#### ④ 기상 리그 (경쟁·소셜형)
- **사용자 조작**: 기상청 중기예보를 참고해 **주간 날씨를 직접 예측**하고 **1주일 후 실제 관측값과 비교**
- **상호작용 흐름**: 중기예보 확인 → 예측값 입력 → 실제 관측값 비교 → 점수 산정 및 결과 발표 → **ELO 레이팅 갱신**
- **학습 성과**: 기상 예측 과정과 예보의 불확실성 이해, 데이터 기반 판단력 향상

### 3-2. AI 오케스트레이터 기반 적응형 학습
- **학습 분석**: 사용자 응답을 누적 분석하여 `weak_tags`를 자동 추출하고 AI 오케스트레이터(Router Chain)가 개인별 학습 경로를 분기
- **집중 학습**: **정답률 60% 미만** 개념은 반복 문제를 제공해 취약 개념 보완
- **일반 학습**: 오늘 날씨 기반 퀴즈를 매일 새롭게 생성해 지속적인 학습 제공
- **심화 학습**: **기후 탐정·기후 시뮬레이터 등 심화 탐구 콘텐츠 자동 추천 및 연결**
- **맞춤형 학습**: 지속적인 재분석으로 개인별 맞춤 문제와 학습 경로 자동 조정

### 3-3. 수준별 사용자 분기 설계
- **초등학생**: 애니메이션과 직관적인 시각화를 중심으로 AI가 기상 용어를 쉬운 표현으로 변환하여 기초 개념 학습 제공
- **중·고등학생**: 중학교 2학년 과학 「날씨와 우리 생활」 등 **교과과정과 연계된 콘텐츠** 및 실제 기상청 데이터를 활용한 탐구 중심 학습 제공
- **일반 성인**: **심층 시뮬레이션과 기상 리그를 중심으로 실전형 학습** 제공

## §4 창의성 및 차별성 (※아이디어 독창성)

### 4-1. 기존 기상교육 콘텐츠 대비 차별화 포인트
- **매일 바뀌는 학습 콘텐츠**: 기상청 실시간 API를 활용 '오늘의 날씨'가 매일 새로운 교재가 되는 학습 구조
- **함께 성장하는 AI**: WeatherBrain이 지속적으로 학습해 사용자가 늘어날수록 모델 정확도와 개인 맞춤형 추천 성능이 함께 향상
- **맥락을 이해하는 AI 피드백**: RAG 기반 기상 지식 검색으로 단순 정답이 아닌 원리 중심의 맞춤형 피드백 제공
- **유연한 AI 운영 구조**: 서버 환경에 따라 **단일 LLM 기반으로도 운영 가능**
- **전문지식의 대중화**: 기상청 데이터를 학습자 수준에 맞는 쉬운 표현으로 재구성하여 누구나 쉽게 이해하는 학습 콘텐츠 제공
- **지속적인 학습 습관 형성**: 스트릭·XP·리그 시스템으로 꾸준한 참여 유도
