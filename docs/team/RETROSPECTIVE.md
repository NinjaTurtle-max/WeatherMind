## 2. 코드 리뷰가 잡은 결함 (커밋 전 차단)

리뷰가 없었으면 조용히 배포됐을 결함들 — 리뷰 프로세스의 실효를 보여주는 지표:

| 스프린트 | 확정 결함 | 성격 |
|---|---|---|
| R2 | 세션 문항을 /quiz 경로로 제출 시 세션 XP 불일치 | 이원화 |
| R2 | nginx 프록시 뒤 레이트리밋이 전역 버킷으로 수렴 | 배포 환경 |
| R2 | 뱅크 공백 시 LLM 5회 직렬 → 세션 발급 8~15s·단일 실패 503 | 성능·강건성 |
| R3 | SessionItem이 board template 미노출 → 세션 내 보드 렌더 불가 | 기능 간극 |
| R4 | AI↔QA 시그니처 불일치 → 재현 퍼즐 게이트 실패 | 교차 직군 |
| R5 | units.json slug vs 로더 자연키 → **선행 잠금 전면 소실** | 기능 무력화 |

R2는 8관점 병렬 리뷰(후보 33건→확정 10건), R3~R5는 PM 타겟 리뷰(각 직군 자체
테스트가 방어). 컨벤션 위반은 전 스프린트 0건 — 계약 선고정 방식의 효과.

## 3. 무엇이 잘 작동했나

- **계약 선고정 → 병렬 무충돌**: 각 스프린트 시작에 서비스 계약(API 스키마·에러 코드·
  DB DDL·시드 스키마)을 §3에 고정하고 4직군이 동시 작업 → 디렉토리 소유권 충돌 0건.
- **단일 진실원 강제**: 보드 규칙(board_rules.json)을 프론트·백엔드가 같은 파일로 해석,
  공유 테스트 벡터(board_test_vectors.json)로 양측 판정 일치를 CI가 상시 보증.
  시드 계약 테스트가 ai-worker 검증기를 실제 임포트(재기술 금지).
- **결정적 폴백 설계**: 품질 게이트·AI 캐스터를 LLM 없이도 동작하게 만들어 키 부재
  환경에서도 전 테스트 실행 가능(457건 전부 DB·LLM 불필요).
- **문서 자산 누적**: TEAM_PROCESS·스프린트 계약·리뷰 노트·회고·런북·콘텐츠 가이드가
  다음 라운드의 컨텍스트로 재사용 — 세션 중단·재개에도 계약이 손실을 방지.

## 4. 무엇이 아쉬웠나 (개선 액션)

- **시드 스키마 미고정이 통합 결함을 낳음(R5)**: API·DDL은 고정했으나 시드 파일 필드
  스키마를 계약에 안 박아 3직군이 다른 해석. → **이후 계약은 시드 파일 필드까지 명시**
  (R5 §3.2 갱신 완료). "공유되는 모든 것에 계약"이 교훈.
- **교차 직군 소유 경계의 마찰(R4)**: celery_app(DevOps)·test(QA)·validator(AI)가 얽힌
  시그니처 변경이 결함. → 공유 시그니처 변경 시 소비자 목록을 계약에 명시.
- **세션 사용량 한도로 에이전트 다회 중단**: 재개 체계(SendMessage로 transcript 복원)로
  산출 손실은 0이었으나 벽시계 시간 증가. 큰 작업은 웨이브 분할 유지.

## 5. 이월 부채 · 로드맵 (미구현 명시)

- **실기동 통합 테스트**: 전 테스트가 순수함수/소스텍스트 기반. docker compose 실기동 +
  실제 KMA/Gemini 키로 INTEGRATION_CHECKLIST 실행은 키 발급 후(체크리스트 준비 완료).
- **로드맵 유지**: 기후 탐정 스토리·AI 캐스터 롤플레이(LLM 키), 웹푸시(구름 회복 알림),
  WeatherBrain IRT 재학습(사용자 데이터 축적 후 — 콜드스타트는 weak_tags·규칙으로 동작).
