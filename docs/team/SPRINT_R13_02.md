# SPRINT R13-02 — 배포 후 본선까지 · 트랙 7개

> **기간** 2026-08-11 ~ 08-20 (배포 8/10 완료 · 본선 8/21)
> **일자 배정은 이 문서가 소유하지 않는다** — `docs/team/CARRYOVER_R13.md` §0 마스터 색인.
> 여기는 **트랙(무엇을 어떤 순서로)**과 **완료 판정**만 적는다.

## 0. 왜 트랙으로 묶는가

R13-01까지는 이월을 **항목 단위**로 배정했다. 269건이 날짜에 흩어지면서 같은 뿌리를
가진 것들이 서로 다른 날에 놓였고, 담당이 하루에 서로 무관한 5건을 만졌다. 실제로
**보드 확장(K2·A3·Z-1)은 셋이 한 몸인데 세 날에 흩어져 있었다** — 앞 둘을 안 하면
셋째가 구조적으로 불가능한데도.

그래서 이번엔 **기능·로직 카테고리로 묶고 트랙 안에서 순서를 고정**한다. 트랙 하나를
하루에 몰아 끝내면 그날 저녁에 그 기능이 **끝까지 동작**한다. 반쯤 열린 상태로
다음 날로 넘어가는 것이 R13-01에서 가장 비쌌다.

## 1. 트랙 7개와 의존

```
T1 저작 엔진 ──────► T2 난이도 체계 ──┬─► T3 세션·실황
   (1,000건의 전제)      (10단계)       └─► T4 보드 확장
T5 정산·보상 루프   (독립 — 실운영 첫날부터)
T6 접근성·i18n      (독립 — 마감 전)
T7 운영·안정성      (상시)
```

**T1이 임계 경로다.** 1,000건 저작은 사람 손으로 불가능하고 생성기가 내야 하는데,
지금 생성기는 **유형 3종만 내고**(CO-O-13) **expert 단계를 못 고른다**(CO-O-6).
T1을 안 고치면 T2·T3·T4의 저작 요구가 전부 공중에 뜬다.

## 2. 트랙별 계약 (완료 판정 = 기계 검증)

### T1 — 저작 엔진 (1,000건의 전제)

| 항목 | 완료 판정 |
|---|---|
| CO-O-13 유형 3종 → **7종** | 생성 배치 50건에서 board 제외 6유형이 모두 1건 이상 |
| CO-O-6 `--level-group`에 expert 추가 | `placement_service.LEVEL_GROUPS`와 CLI 선택지가 같다 |
| CO-O-8 route·target_concept_tag를 SYSTEM 프롬프트에 | 프롬프트 원문에 두 필드가 등장 |
| CO-E-4·O-9 난이도 신호 소실 (수리 지점 **2곳**) | `ai_client.quiz_generate` · ai-worker HTTP 양쪽 |
| CO-E-5 개념 화이트리스트 8종 → **14종** | 생성 요청이 14개념 전건을 받는다 |
| CO-B4 신고 단계 표본 검수 | 배치당 10건 사람 검수 · 오분류율 기록 |

> ⚠️ **게이트는 어휘만 본다.** 어휘가 쉬운데 개념이 어려운 문항을 못 잡는다 —
> 그래서 B4(표본 검수)가 자동화의 대체재가 아니라 **필수 동반**이다.

### T2 — 난이도 체계 (10단계)

| 284건 **재분류** 1~6 → 1~10 | 2축 정합 위반 0건 유지 |

> 재분류는 **저작보다 먼저**다. 분류가 바뀌면 저작 배분도 바뀐다.

### T3 — 세션·실황 (오늘의 세션 재정의)

| 항목 | 완료 판정 |
|---|---|
| **현상 판정 함수** (KMA 값 → phenomenon) | 순수 함수 · backend↔celery 계약 테스트 |
| 보드 매칭 (오늘 현상 → 보드, 없으면 `board_order`) | 9종 어휘 전건 매칭 가능 |
| 실황 문항 **+12건** (현상 16 + 계산 4 구조) | 정답이 `today.*`를 참조하는 문항 ≥ 4건 |
| 개황 지문 (브리핑 상단) | **정답 판정에 쓰지 않는다** |
| 배합 전환 `{new:4, review:3, live:2, board:1}` = 10 | `.env.example` 기본값 + 계약 테스트 동시 |

> 지금 실황 자산은 **8건 · 전부 MC · 정답 고정**이다. MC로는 정답이 날마다 못 바뀐다 —

## 3. 저작 총량 — 1,000건

| 구분 | 건수 |
|---|---|
| 현재 | 284 |
| **생성기 산출**(T1 이후) | **~650** |
| 사람 저작 (실황·전문가·F축·검수 반려분) | ~70 |
| **목표** | **~1,000** |

**생성기가 주력이고 사람은 검수·상위·실황을 맡는다.** 사람 손으로 716건은 불가능하다.
`CO-B7`(오픈 모델 채택 판정)이 여기 붙는다 — 1~5단계 대량은 OSS, 6단계 이상 소량은
Gemini, 런타임은 Gemini.

⚠️ **총량은 목표이지 계약이 아니다.** 게이트 통과율이 60% 미만이면 총량을 낮추는 것이
아니라 **그 사실을 보고한다**(R13-01 §2 관례).

## 4. 공통 금지

- 트랙을 **반쯤 열고 다음 날로 넘기지 않는다.** 하루에 트랙 하나를 끝까지.
- 배정을 이 문서에 적지 않는다 — 대장 §0이 소유한다.
- 저작 총량 미달 시 **임계를 낮추지 않는다.** 미달을 보고한다.
- `/code-review` 게이트는 위임 불가 — PM이 브랜치 단위로 직접.
